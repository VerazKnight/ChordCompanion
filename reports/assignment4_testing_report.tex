\section{Overview}
ChordCompanion is a piano and chord-learning application. The supplied run
reports \textbf{42 passed, 0 failed}: 33 unit tests and 9 component tests.
GoogleTest and CTest exercise input state, piano layout and chord analysis
without a window, audio output or MIDI device.

\subsection{Four selected units}
\begin{enumerate}
\item \textbf{NoteState class} (4 tests, IDs 1--4): updates held notes and produces
note-on/off events. This tests the input-model responsibility of PianoKeyboard.
Shared UI/MIDI notes remain held until their last owner releases them.
\item \textbf{PianoLayout::noteAtPoint} (4 tests, IDs 22--25): converts a piano-local
mouse position into a MIDI note or -1. This supports UI's click-on-piano use case.
\item \textbf{ChordTheory::identifyChord} (4 tests, IDs 26--29): determines a chord's
root, type and inversion from held notes for the current UI.
\item \textbf{ChordTheory::detectKey} (4 tests, IDs 30--33): estimates a major key
from recognized chord history, including a relative-major result for minor
progressions. This supports the UI's added history analysis.
\end{enumerate}
These four units have 16 tests, exceeding the required 12. Additional unit tests
cover ChordLogic (8, IDs 5--12) and PianoLayout helpers (9, IDs 13--21).

\subsection{Two selected components}
\begin{enumerate}
\item \textbf{Note-input interpretation} (5 tests, IDs 34--38): combines PianoLayout,
NoteState and ChordTheory to interpret resolved UI/MIDI notes, identify chords,
and describe visible keys. Cases include successful chord formation, outside hits,
incomplete chords and shared-source release.
\item \textbf{Chord-progression analysis} (4 tests, IDs 39--42): sends real
identifyChord results into a PlayedChord history and detectKey. This combines
chord recognition and history analysis. Cases include a normal progression,
unrecognized snapshots, an outside-key chord and inverted voicings.
\end{enumerate}
Both components use real computational functions and fixed test data.

\section{Remaining failures and limitations}
No tests failed in the supplied run. Coverage excludes real devices, audio,
rendering, QWERTY mapping, mouse latching, concurrency and the full MainApp loop.
Component tests do not execute UI frame timing or history management.
ChordLogic supports its implemented major-triad table; UI still uses
ChordTheory. Invalid NoteState input rejection and other operating systems
need further testing.

# ChordCompanion

Group project for Software Engineering: a piano and chord-learning application.

Run all commands below from the repository root.

## Initialize dependencies

After cloning, run:

```sh
git submodule update --init --recursive
```

This downloads the bundled dependencies.

### Windows

With Visual Studio’s C++ build tools installed, using the Visual Studio generator, from the root: 

```powershell
cmake -S . -B build -A x64 -DBUILD_TESTING=ON
cmake --build build --config Debug --target ChordCompanion --parallel 2
.\build\Debug\ChordCompanion.exe
```

After configuring with the Windows commands above, run tests with:

```powershell
cmake --build build --config Debug --target check --parallel 2
```

### Linux / Mac

With the project's dependencies installed, from the root:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --target ChordCompanion --parallel 2
./build/ChordCompanion
```

Then build and run all unit tests:

```sh
cmake --build build --target check --parallel 2
```

### Test output

The `check` target rebuilds the tests before running them, prints diagnostic
output for failures, and returns a nonzero exit code if a test fails.
\end{lstlisting}
